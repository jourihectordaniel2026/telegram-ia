Este sistema se arma con 3 prompts

1 · CONSTRUIR 
Armá un bot de Telegram para una librería escolar de
Argentina que haga presupuestos con IA.
Stack: Python, Claude con tool use, PostgreSQL y Docker Compose.

- Base de datos: categorías, artículos (precio y stock),
  usuarios, presupuestos con ítems e historial de mensajes.
  Cargá unos 70 artículos de ejemplo.
- Tools: buscar artículos (tolerante a acentos y errores de
  tipeo), crear, modificar y listar presupuestos, generar PDF.
- La IA nunca inventa precios: todo sale de la base.
- Que recuerde la conversación y datos del cliente.
- PDF con N°, fecha, validez, ítems, subtotales y total.
2 · COMPORTAMIENTO 
Escribí el system prompt: español rioplatense, respuestas cortas y sin Markdown. Que entienda "birome", "plasticola", "fibrón"; que pregunte si el pedido es ambiguo; que muestre un resumen y pida confirmación antes del PDF; y que no dé descuentos ni hable de otros temas.
3 · PROBAR Y AJUSTAR 
Levantá todo con Docker y probalo de punta a punta: pedí "5 cuadernos rayados y una resma", modificá el presupuesto y generá el PDF. Corregí lo que falle.

Cambiá "librería" por tu rubro —ferretería, farmacia, repuestos— y el mismo esquema te sirve.

La idea

De un mensaje en lenguaje natural a un presupuesto formal

💬

1. El cliente escribe

Como le escribiría a un empleado: “5 biromes azules y una plasticola”.

🧠

2. La IA interpreta

Entiende qué artículos y cantidades pide, y si falta información, pregunta.

🔎

3. Consulta la base

Busca precios y stock reales. Nunca inventa un dato: todo sale del catálogo.

📄

4. Entrega el PDF

Arma el presupuesto, lo guarda y lo envía por el mismo chat.

La clave: la IA no responde de memoria. Decide qué hacer y usa herramientas programadas por nosotros para leer y escribir datos reales.

Precio congelado

El ítem copia nombre y precio al presupuestar: si mañana sube el precio, el presupuesto emitido no cambia.

Totales con trigger

Un trigger recalcula subtotal y total cada vez que se agrega, cambia o quita un ítem.

Búsqueda tolerante

Extensiones unaccent + pg_trgm: “lapiz” encuentra “Lápiz”, “cuadernos” encuentra “Cuaderno”.

memory.py

Memory: la IA recuerda

🕑 Corto plazo · la conversación

  • Cada mensaje se guarda en la tabla mensajes como JSONB, incluidas las llamadas a tools.
  • En cada consulta se envían los últimos 40 mensajes; el recorte siempre empieza en un mensaje del usuario, nunca a mitad de una tool.
  • El turno se guarda completo y de una vez: si algo falla a mitad de camino, no queda un historial roto.
  • /nuevo empieza una conversación limpia.

🗂️ Largo plazo · el cliente

  • Tabla memoria_usuario con pares clave/valor: nombre, colegio, grado, marca preferida.
  • La IA decide qué vale la pena recordar y lo guarda con la tool recordar_dato_cliente.
  • En cada mensaje se le recuerda:
[Fecha: 08/10/2026 17:49]
[Datos recordados del cliente: nombre: Mauricio; colegio: San Martín]
pasame mi último presupuesto

💡 La memoria vive en la base de datos, no en el modelo: el modelo no “aprende”, se le vuelve a dar contexto en cada llamada.

prompts.py · System prompt

Un comportamiento definido

🚫 Nunca inventa precios, artículos ni stock: todo sale de las tools.

🤔 Si el pedido es ambiguo, ofrece 2 o 3 opciones concretas del catálogo.

📦 Si falta stock, avisa y propone alternativas.

✅ Muestra un resumen y pide confirmación antes de generar el PDF.

🗣️ Entiende términos coloquiales: birome, fibrón, plasticola, voligoma.

🎯 Solo temas de la librería. No da descuentos ni confirma ventas.

main.py

El bot de Telegram

Conexión

Bot creado con @BotFather. La librería python-telegram-bot consulta a Telegram si hay mensajes nuevos (long polling): no hace falta servidor público.

Comandos

  • /start saludo y ejemplos
  • /nuevo conversación nueva
  • /presupuestos lista los del usuario
  • Cualquier texto va al agente

Detalles

  • Indicador “escribiendo…” mientras piensa
  • Un lock por chat: mensajes seguidos se procesan en orden
  • Respuestas largas se parten en partes de 4000 caracteres
  • Los PDFs se envían como documento

⚠️ Manejo de errores: si la API falla (clave inválida, límite de uso, sin conexión) el usuario recibe un mensaje amable y el error completo queda en docker compose logs bot. Así detectamos el 401 invalid x-api-key durante la puesta en marcha.

Decisiones de diseño

Seguridad y robustez

🔒

Aislamiento por usuario

Toda consulta de presupuestos filtra por chat_id, y ese dato lo pone el código, no la IA.

🧾

La IA no escribe SQL

Solo puede usar las 11 tools. Cada una valida sus datos (código existente, cantidad > 0).

🔁

Errores como información

Si una tool falla, el error vuelve a la IA (is_error) y ella se lo explica al cliente.

⏱️

Límites

Máximo 10 vueltas de tools por mensaje. Lista opcional de chats autorizados (TELEGRAM_ALLOWED_CHAT_IDS).

🔑

Secretos fuera del código

Token de Telegram y API key en .env, nunca en el repositorio.

💸

Costo controlado

Modelo configurable (CLAUDE_MODEL) y prompt caching del prefijo fijo.

Resumen

Una IA útil = modelo + herramientas + datos + memoria + reglas claras
